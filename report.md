## 1. Цель работы

Цель лабораторной работы — закрепить навыки использования коллективных операций MPI (`Scatter`, `Scatterv`, `Reduce`, `Allreduce`) и реализовать параллельные алгоритмы вычисления скалярного произведения векторов и умножения транспонированной матрицы на вектор. Полученные алгоритмы также являются компонентами, которые могут использоваться при реализации метода сопряжённых градиентов.

## 2. Постановка задачи

В лабораторной работе реализованы две вычислительные задачи.

**Часть 1. Скалярное произведение.** 
Требуется вычислить скалярное произведение вектора на самого себя. Вектор создаётся процессом с рангом 0. Его элементы распределяются между процессами, после чего каждый процесс вычисляет локальное скалярное произведение. Частичные результаты суммируются операцией MPI.

**Часть 2. Умножение транспонированной матрицы на вектор.** 
Матрица разбивается на горизонтальные блоки строк. Каждому процессу передаются соответствующий блок матрицы и соответствующий блок вектора. Локальные результаты суммируются на процессе с рангом 0.

## 3. Используемые средства

В работе используются:

- **Python** — язык программирования;
- **NumPy** — создание и обработка массивов, локальные вычисления с помощью `numpy.dot`;
- **mpi4py** — взаимодействие с MPI из Python;
- **OpenMPI или MPICH** — реализация стандарта MPI;
- **pytest** — автоматизированное тестирование программ.

Для запуска параллельных программ используется команда `mpiexec` (в некоторых MPI-средах также доступна команда `mpirun`).

## 5. Часть 1. Параллельное вычисление скалярного произведения

### 5.1. Алгоритм работы программы

Реализация находится в файле `src/parallel_dot_product.py`.

Процесс с рангом 0 создаёт вектор длины \(M=20\) с помощью NumPy:

```python
a = arange(1, M + 1, dtype=float64)
```

В данной реализации процесс с рангом 0 выполняет роль координатора: создаёт исходный вектор, рассчитывает параметры распределения и получает итоговое значение. Вычислительная работа распределяется между процессами с рангами от 1 до \(P-1\), где \(P\) — общее количество MPI-процессов.

Количество рабочих процессов равно \(P-1\). Для распределения элементов используется `divmod(M, numprocs - 1)`. Частное определяет базовое количество элементов на рабочий процесс, а остаток — количество процессов, которые получат на один элемент больше. Таким образом, распределение остаётся корректным, даже если \(M\) не делится на число рабочих процессов нацело.

Для передачи размеров локальных блоков используется `Scatter`. Массивы `rcounts` и `displs` задают количество элементов и смещение каждого блока в исходном векторе. Сам вектор распределяется между процессами с помощью `Scatterv`.

После получения своего блока `a_part` каждый процесс вычисляет локальное скалярное произведение:

```python
ScalP_temp[0] = dot(a_part, a_part)
```

Затем частичные результаты складываются операцией `Reduce` с операцией `MPI.SUM`. Итоговое значение собирается на процессе с рангом 0.

Процесс 0 дополнительно вычисляет контрольное значение последовательным способом:

```python
ScalP_seq = dot(a, a)
```

Параллельный и последовательный результаты сравниваются с заданным числовым допуском. Это позволяет проверить корректность распределения данных и суммирования частичных результатов.

### 5.2. Используемые коллективные операции

| Операция | Назначение |
|---|---|
| `Scatter` | Передача каждому процессу количества элементов его локального блока |
| `Scatterv` | Распределение блоков исходного вектора разного размера |
| `Reduce` с `MPI.SUM` | Суммирование локальных скалярных произведений и получение результата на процессе 0 |

В задании также предусмотрен вариант с `Allreduce`. В реализованной программе используется `Reduce`, поскольку для проверки и дальнейшего вывода итогового значения достаточно получить результат на процессе с рангом 0. `Allreduce` потребовался бы в том случае, если бы итоговое скалярное произведение должно было быть доступно каждому процессу.

### 5.3. Проверка результата

Для вектора \(a=(1,2,\ldots,20)\) контрольное значение равно:

\[
s = 1^2 + 2^2 + \ldots + 20^2 = 2870.
\]

При успешном выполнении программа должна вывести одинаковые параллельный и последовательный результаты и сообщение о прохождении проверки.

## 6. Часть 2. Умножение транспонированной матрицы на вектор

### 6.1. Входные данные

Реализация находится в файле `src/parallel_matvec.py`.

Исходные данные считываются процессом с рангом 0 из трёх файлов:

- `data/in.dat` — размеры матрицы: сначала \(N\), затем \(M\), каждое значение записано на отдельной строке;
- `data/AData.dat` — элементы матрицы \(A\), записанные построчно;
- `data/xData.dat` — элементы вектора \(x\).

Матрица преобразуется в массив размера \(M \times N\), а вектор — в массив длины \(M\). В программе используется `reshape`, чтобы явно задать требуемые размеры массивов.

### 6.2. Распределение данных

Процесс 0 считывает размеры матрицы. Значение \(N\) передаётся остальным процессам с помощью `Bcast`. Значение \(M\) используется процессом 0 для расчёта размеров блоков.

Матрица разбивается на горизонтальные полосы, то есть каждый процесс получает несколько целых строк матрицы. Вектор \(x\) разбивается согласованно: процесс, получивший определённые строки матрицы, получает элементы вектора с теми же индексами.

Для распределения используются массивы `rcounts` и `displs`. Поскольку в матрице у каждой строки \(N\) элементов, количество передаваемых элементов матрицы для процесса вычисляется как:

\[
sendA_k = rcounts_k \cdot N,
\]

а смещение:

\[
displsA_k = displs_k \cdot N.
\]

Распределение матрицы и вектора выполняется с помощью двух вызовов `Scatterv`. Размер локального блока строк перед этим передаётся отдельной операцией `Scatter`.

Как и в первой части, процесс с рангом 0 является координатором и не получает блок строк для вычислений. Строки распределяются между процессами с рангами от 1 до \(P-1\). Если количество строк не делится на число рабочих процессов нацело, остаток распределяется по одной дополнительной строке между первыми рабочими процессами.

### 6.3. Локальные вычисления и редукция

Получив блок матрицы `A_part` размера `local_M × N` и соответствующий блок вектора `x_part` длины `local_M`, каждый процесс вычисляет:

```python
b_temp = dot(A_part.T, x_part)
```

Результат `b_temp` имеет длину \(N\). Каждый его элемент является частичной суммой для соответствующего столбца исходной матрицы.

Итоговый вектор получается суммированием локальных векторов:

\[
b = \sum_{k=1}^{P-1} b^{(k)}_{\text{temp}}.
\]

Для этого используется коллективная операция `Reduce` с операцией `MPI.SUM`. Итоговый вектор `b` формируется на процессе с рангом 0.

Затем процесс 0 вычисляет контрольный результат последовательным способом:

```python
b_seq = dot(A.T, x)
```

Параллельный результат сравнивается с последовательным. Для проверки используется допуск, учитывающий возможные небольшие различия при вычислениях с плавающей точкой. При выводе элементов векторов используется формат с 17 значащими цифрами, чтобы тесты могли считывать значения с достаточной точностью.

### 6.4. Почему используется Reduce, а не Gatherv

В данной задаче каждый процесс вычисляет вектор длины \(N\). Эти локальные векторы не являются отдельными непересекающимися частями итогового результата. Каждый из них содержит частичные суммы для всех \(N\) элементов вектора \(b\).

Поэтому необходимо выполнить поэлементное сложение локальных векторов:

\[
b_j = \sum_{k=1}^{P-1} b^{(k)}_{\text{temp},j},
\quad j=0,\ldots,N-1.
\]

Операция `Reduce` с `MPI.SUM` непосредственно выполняет такое суммирование и возвращает итоговый вектор процессу 0.

`Gatherv` предназначена для сбора отдельных блоков данных в общий буфер. Она не складывает значения с одинаковыми индексами. При использовании `Gatherv` процесс 0 получил бы набор локальных векторов, после чего ему пришлось бы самостоятельно суммировать их элементы. Следовательно, `Reduce` лучше соответствует математической операции, необходимой для вычисления \(A^T x\).

## 10. Вывод

В ходе лабораторной работы реализованы две параллельные вычислительные задачи с использованием коллективных операций MPI.

В первой части реализовано вычисление скалярного произведения вектора на самого себя. Исходный вектор распределяется между рабочими процессами с помощью `Scatterv`, а локальные скалярные произведения объединяются операцией `Reduce` с `MPI.SUM`. Дополнительно выполняется последовательное вычисление для проверки корректности результата.

Во второй части реализовано умножение транспонированной матрицы на вектор. Матрица распределяется горизонтальными блоками, а вектор разбивается согласованно с блоками строк матрицы. Каждый процесс вычисляет локальный вектор длины \(N\), после чего локальные результаты поэлементно суммируются операцией `Reduce` с `MPI.SUM`.

В работе рассмотрено отличие `Reduce` от `Gatherv`: первая операция суммирует значения с одинаковыми индексами, тогда как вторая собирает отдельные блоки данных без выполнения арифметического объединения. Поэтому для получения результата \(A^T x\) используется именно `Reduce`.

Во всех 12 экспериментальных запусках параллельные и последовательные результаты совпали. В первой части получено значение 2870, во второй совпали все 150 компонент результирующего вектора. Все 7 автоматизированных тестов пройдены, включая сценарии с неравномерным распределением и пустым блоком. На исследованных данных переход к четырём MPI-процессам не сократил медианное время ни одной из задач.
